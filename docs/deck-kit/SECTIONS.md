# Sections and visuals

Generated by `node catalog.cjs` from `visual-map.json`. Edit the JSON, not this file.

13 slides. 10 carry a generated diagram; the rest are
deliberately type-only — a visual there competes with the line you want heard.

## The slides

| Slide | What it is for | Visual | Done when |
|---|---|---|---|
| `cover` | Name plus the one line you want repeated back. | — | Someone who missed the title can still say what you do. |
| `problem` | The pain, dated and specific — not a category. | `timeline` | A listener has personally felt it. |
| `insight` | The non-obvious thing you know that others don't. | `split` | It is not a feature, and a competitor would argue with it. |
| `solution` | What you built, in three verbs. | `flow` | No adjectives survive on the slide. |
| `whynow` | Why this is buildable now and wasn't two years ago. | `timeline` | Every mark is a real shift, not a trend word. |
| `product` | The pipeline, one hand-off per arrow. | `flow` | It asks the user to change no habits. |
| `market` | Bottom-up arithmetic you can defend. | `stack` | Every term is counted and cited, none borrowed. |
| `competition` | Two axes that leave you alone in one corner. | `quadrant` | The axes are true even if a rival drew them. |
| `model` | Who pays, how much, per what. | — | It names the buyer, not the user. |
| `traction` | Only what you have actually measured. | `bars` | Every number can be reproduced live. |
| `team` | Why these specific people. | `flow` | The why-us line would be false for any other team. |
| `vision` | The wedge expanding into a company. | `rings` | It is a company, not a bigger feature. |
| `ask` | What you want, and the biggest risk named first. | — | The risk is on the slide before they ask it. |

## The seven recipes

Every recipe emits `div` / `p` / `x-shape` markup styled from theme tokens, written
**into the slide file itself**. No images, no external URLs. Swapping themes recolors
every diagram with no edit to any slide.

### `timeline`

Something decaying, or a sequence of enabling shifts. `hot` paints one mark in the risk color.

```js
{ marks: [{ label, sub, hot? }] }
```

Height: 300px equivalent.

### `split`

An asymmetry — one side handled, the other not. Right panel reads as the problem.

```js
{ left: {kicker,title,body}, right: {kicker,title,body} }
```

Height: ~340px equivalent.

### `flow`

A pipeline or a hand-off chain, 2-4 stages. Arrows between, themed.

```js
{ steps: [{ title, body }] }
```

Height: ~190px equivalent.

### `stack`

Bottom-up multiplication shown as the arithmetic itself. The total is outlined in the accent.

```js
{ terms: [{value,label}], total: {value,label} }
```

Height: ~210px equivalent.

### `bars`

Measured numbers only. `pct` drives bar width, `value` is the printed figure.

```js
{ rows: [{ label, pct, value, hot? }] }
```

Height: autopx equivalent.

### `quadrant`

Positioning map. x and y are 0-1 fractions; `hot` is you.

```js
{ poles: {top,bottom,left,right}, points: [{x,y,label,sub,hot?}] }
```

Height: 460px equivalent.

### `rings`

A wedge expanding. layers[0] is what you sell today and draws filled; up to 4.

```js
{ layers: [{ label, sub }] }
```

Height: 440px equivalent.

## When the data isn't there

The build never invents a figure. A slide missing its data renders the fallback and
`build.cjs` prints which fired.

| Slide | Needs | Falls back to |
|---|---|---|
| `problem` | marks[]{label,sub,hot} | prose only |
| `insight` | left{kicker,title,body}, right{kicker,title,body} | prose only |
| `solution` | steps[]{title,body} | prose only |
| `whynow` | marks[]{label,sub,hot} | prose only |
| `product` | steps[]{title,body} | prose only |
| `market` | terms[]{value,label}, total{value,label} | em dashes in every cell plus an 'unsourced' footer |
| `competition` | xAxis, yAxis, points[]{x,y,label,sub,hot} | three-row table |
| `traction` | rows[]{label,pct,value,hot} | big-number slide plus 'nothing else is true yet' |
| `team` | steps[]{title,body} | cards |
| `vision` | layers[]{label,sub} | statement slide |

## Cannot be generated

- **product screenshot** — Must be captured from the running project — see capture.sh. Uploaded as a deck asset and referenced as /_blob/<id>; it is the one visual that does NOT live inside the slide file.
- **photos** — Team photos, venue shots, anything real. Supply the file; never generate a stand-in that reads as real.
- **logos** — Customer or partner logos. Only ones you have permission to show.
